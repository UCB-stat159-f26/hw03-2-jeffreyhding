Question:
Should the pyproject.toml file be done towards the start of creating a Python package or near the end?

Response:
It should be done toward the start, after you've established the basic package name/layout but before you've developed much functionality.

The reason is that pyproject.toml isn't final cleanup or documentation. It defines how the package is built and installed, along with core package metadata and dependencies. Having it early means we can install tenniscareer in editable mode while developing it and continuously verify that we're actually building an installable package—the exact thing HW03 will ultimately grade by installing directly from GitHub.


Question:
How do I implement tests for a Python package?

Response:
Use pytest and place test files in the package's tests/ directory, with filenames beginning with test_. Each test calls a package function with controlled input and uses assert statements to check that the output matches the expected behavior. For functions that normally depend on external websites, tests should use fixed mock data instead of making live web requests. This makes the tests fast, reproducible, and independent of whether the external website is available. The full package test suite can then be run with pytest tenniscareer.


Question:
Is there any particular library/package to use for handle error handling? Is a command line text message good enough?

Response:
No extra library is needed. Python has built-in exception handling, and since the package is already using urllib to make requests, urllib.error.HTTPError is a natural exception to catch when a requested Tennis Abstract page does not exist.

Instead of only printing a command-line message such as "Player not found," it is better to raise a clearer exception, such as ValueError("Player not found: ..."). Printing a message tells the user what happened, but raising an exception also signals to other code and tests that the operation failed. A custom exception could be created, but ValueError is sufficient for this assignment.


Question:
How do you meaningfully test a plotting function?

Response:
A plotting function should usually be tested by checking the structure and properties of the Matplotlib objects it creates rather than comparing image files pixel-by-pixel. For example, a test can verify that the function returns a Figure and Axes, that the expected title and axis labels are present, and that the correct number of plotted data series or legend entries were created.

This makes the test more stable than image comparison because small rendering differences between Matplotlib versions or operating systems do not cause failures. Visual inspection can still be useful during development, but automated tests should focus on the plot's intended behavior and content.
